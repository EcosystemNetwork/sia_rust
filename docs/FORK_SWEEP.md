## Finding 1 — SIA² Spectral Improvement Architecture  ⭐ HIGH leverage

**Source (pinned):**
- [`sia/spectral_orchestrator.py`](https://github.com/SuperInstance/sia/blob/1621fc50925b0144e3a32afd9a14ebfd3c4d03e8/sia/spectral_orchestrator.py) (893 LOC)
- [`sia/spectral_integration.py`](https://github.com/SuperInstance/sia/blob/1621fc50925b0144e3a32afd9a14ebfd3c4d03e8/sia/spectral_integration.py) (592 LOC)
- [`README_SIA2.md`](https://github.com/SuperInstance/sia/blob/1621fc50925b0144e3a32afd9a14ebfd3c4d03e8/README_SIA2.md)
- Compare: <https://github.com/hexo-ai/sia/compare/main...SuperInstance:main>

**What it does.** Replaces SIA's linear `Meta → Target → Feedback → repeat`
loop with a *spectral* loop: (1) decompose agent performance into eigenmodes,
(2) identify the weakest mode via a spectral-gap threshold, (3) improve that
mode specifically, (4) verify "conservation laws" hold (no capability lost),
(5) iterate toward a Banach fixed point. Ships `SpectralMode`,
`ConservationLaw`, and `ImprovementStep` dataclasses with numpy math.

**Why it's relevant to the Rust port.** Two of our modules map cleanly onto it:
- **`src/scheduler.rs` (adaptive scheduler, #65)** — "improve the weakest
  eigenmode next" is a concrete, novel *scheduling policy* for which generation/
  context to feed back. Today our scheduler adjusts the feedback window
  heuristically; spectral-gap selection is a principled alternative.
- **`src/verifier.rs` (Goodhart robustness)** — the **conservation-law check**
  ("no capability lost during improvement") is exactly a regression-guard
  against Goodhart over-fitting. It's a *novel evaluation method* — i.e. direct
  Research-track material.

**Recommendation: `adapt`, not cherry-pick.**
- It's unproven Python (~1,500 LOC, ambitious "14 theorems" framing, no
  empirical results in the fork). Do **not** port wholesale.
- **Do** adopt two ideas, natively in Rust, behind a feature flag:
  1. *Conservation-law / capability-regression guard* in the verifier — cheap,
     high-value, testable offline.
  2. *Weakest-mode-first scheduling* as an opt-in `SchedulerPolicy` variant.
- Keep the empirical bar honest: only claim a win if `runs/` telemetry shows it
  beats the linear loop on a bundled task.

**Maps to umbrella:** harness-update loop / scheduler work (#65), verifier (#66).
